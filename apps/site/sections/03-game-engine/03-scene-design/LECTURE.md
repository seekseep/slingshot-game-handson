# 03 画面（シーン）の設計

![画面（シーン）の設計](./images/00-thumbnail.svg)

このゲームには「スタート画面」「ゲーム本編」「クリア／ゲームオーバー画面」があります。
Phaser では、これらを **シーン（Scene）** という単位で分けて作ります。この節では、
なぜ画面を分けるのか、どう切り替わるのかを整理します。

## なぜ画面を分けるのか

もし全部を1つの画面に詰め込むと、「今はタイトル中か、ゲーム中か、結果表示中か」を自分で
管理しなければならず、コードがこんがらがります。シーンに分けておくと、それぞれの画面が
自分の仕事だけに集中できて、見通しがよくなります。

- `StartScene` … タイトルとスタートボタンを出す。
- `GameScene` … パチンコ・箱・ブタ・スコアなど、遊びの本体。
- `ClearScene` / `GameOverScene` … 結果を見せて、スタートに戻す。

## シーンの切り替わり

シーンは `this.scene.start('名前')` で切り替えます。このゲームの流れはこうです。

```text
Start ──(スタート)──▶ Game ──(全ブタ撃破)──▶ Clear ──(クリック)──▶ Start
                        └──(弾切れ)──────▶ GameOver ──(クリック)──▶ Start
```

- スタートボタンで `Game` へ。
- ブタを全部倒すと `Clear` へ、鳥を撃ち切ると `GameOver` へ。
- 結果画面をクリックすると `Start` へ戻り、また遊べます。

## データを渡す

シーンを切り替えるとき、`this.scene.start('Clear', { score })` のように**データを一緒に渡せます**。
リザルトの章では、これを使ってゲーム画面のスコアを結果画面へ渡し、表示していました。

このように「画面ごとにシーンを分け、切り替えとデータの受け渡しで つなぐ」のが、Phaser での
画面設計の基本です。次の章では、このシーンの上に、標的やスコアといったゲームのルールを
のせていきます。
